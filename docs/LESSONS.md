# 踩过的坑

第一支片子（2026-10，AI 建网站搬上服务器）从 P0 到完整版遇到的问题和根因。新 Agent 先读一遍能少走很多弯路。

## 配音

| 现象 | 根因 | 解决 |
|---|---|---|
| 生成到一半报 429 | Gemini TTS 免费版每天 10 次调用，按镜头调用很快用完 | 整片一次调用（`voice` 默认），按逐字时间戳切回镜头 |
| 偶发 503 | 服务端繁忙 | 脚本自动重试；503 一般不计入次数 |
| IP 被念成「四十七点九十八」 | TTS 按数值读 | 台词里写「四七点九八」，字幕再换回 47.98 |
| 语速偏慢（4.9 字/秒） | 提示词没约束 | 风格提示里写「每秒五到六个字、句间停顿短」→ 5.4 字/秒 |
| 整片一次生成时，部分提问句（常在镜头第一句）被念成女声 | 多人对话 TTS 在长音频里偶尔串声 | 生成请求里说话人名带身份和性别（「主讲·女」「提问·男」）+ 提示词写明男女声；仍串声则**整段重新生成**，由用户听合集确认（**不拼接**，见下一行） |
| 修复的句子末尾带着下一句开头一点 | 单人模式把多句连着念，句间停顿很短；切割时在最后一个字后加了固定 0.12 秒余量，且对齐对句尾字的结束时间不准 | 改进切法后识别复核虽然通过，但用户决定**不采用拼接**，恢复最初一版。**规则：配音不拼接，始终整段对话生成**；拼接工具已删除 |
| 自动音高检查误报 | 自相关音高有倍频误差（男声 112Hz 测成 224Hz），提问句尾音也会抬高 | `voicecheck` 只作提示；**角色是否串声以人耳听 `rolereview` 合集为准** |
| 单人版不如对话自然 | 稿子是书面讲解 | 用双人对话稿（见 SCRIPT_GUIDE） |

## 对齐

| 现象 | 根因 | 解决 |
|---|---|---|
| 4 分钟以上音频对齐内存爆 | wav2vec2 计算量随长度平方增长 | 滑动窗口，每窗约 110 字，窗口最后一句留给下一窗 |
| 本机没有 ffmpeg | whisperx.load_audio 依赖 ffmpeg | 直接读 WAV + scipy 重采样到 16k |

## 画面

| 现象 | 根因 | 解决 |
|---|---|---|
| 高亮的格子和口播对不上 | 关键词写错（台词是「通水通电」，配的是「水电」），找不到时静默退回句首 | `check_shots` 渲染前强制校验 |
| 画面比口播晚一拍 | 关键词放在短句末尾 | 关键词放短句开头 |
| 一上来就是放大的局部，看不懂 | 直接推近 | 换图时先全图框出位置再推近 |
| 多步骤高亮一亮一暗刺眼 | 每步重做遮罩淡入 | 遮罩保持，高亮框滑动 |
| 单帧黑屏（随机） | 超大 box-shadow 遮罩 + 2700px 大图，浏览器偶尔来不及绘制 | 遮罩用 4 块矩形拼；图片最长边缩到 2200 |
| 整帧全黑（连顶栏字幕都没有），随机约 1/25000 帧 | 浏览器偶发截图失败，不是画面逻辑问题 | `a2v render` 扫描到黑帧就自动重渲（最多 3 次） |
| 镜头交界闪黑 | 镜头开头到第一句台词之间画面区为空 | 第一个画面从镜头开头显示 |
| 切图时先亮后暗 / 透出黑底 | 遮罩没跟随图片淡入淡出；双方同时半透明 | 遮罩随图片过渡；新图在上淡入、旧图后淡出 |
| 面板挡住顶栏 | 面板铺满全屏 | 面板只盖画面区 |
| 402 弹出「抖动」卡顿 | 抖动频率高于 30fps 采样 | 改平滑缩放淡入 |
| 插画被识别出一堆「红框」 | 橙色调接近红色 | 插画不用 rb，手写坐标 |

## 质检方法

- `./a2v render` 自带黑帧扫描（逐帧亮度骤降检测），必须 0 处。
- `./a2v qa` 在每个画面停稳时抽帧，配合 `index.txt` 的口播逐张核对 —— 这一步发现了大部分问题。
- `pipeline/flicker.py <视频> <起始秒> <时长>`：测量一段的帧间亮度跳变，用来验证闪烁修复。
- 抽帧要用精确跳转（`-i` 之后再 `-ss`），快速跳转会解出残帧造成误报。

## 隐私（2026-10-06）

| 现象 | 根因 | 解决 |
|---|---|---|
| GitHub 提交作者显示用户真名 | 新仓库没配提交身份、也没有全局身份，Git 自动回退成 macOS 账户全名 + 主机名邮箱；只扫文件内容看不到这一点 | 仓库本地配置 `AI Hub` + noreply 邮箱，`user.useConfigOnly=true` 禁止回退；装 `githooks/` 身份白名单防护 |
| 脚本里有 `/Users/<用户名>/...` | 写死本机绝对路径 | 改用 `$HOME` / `A2V_PYTHON` 环境变量 |

## 脚本

- **不要用 `pkill -f <模式>` 之类的模式匹配去结束进程**：同一台电脑上可能有别的项目/会话也在跑 `remotion render`。只停止自己启动的任务（记下任务 ID / 进程号再停）。

- zsh 里 `LINES`、`COLUMNS` 是特殊变量（只能存数字），不要用作普通变量名。
- 管道里的报错默认会被吞掉：脚本要 `set -e; setopt pipefail`，否则出错后还会带着错误继续往下跑。

## 其他

- 截图的隐私信息：作者已打码；新文章仍要检查 IP、账号、手机号。
- 飞书 CLI「一键创建应用」会默认开很宽的权限，登录时要指定只读 scope，用完 logout。
- 公众号图片最宽 1080px，飞书原图可达 2880px —— 有飞书链接优先用飞书。


## 宣传片（2026-10-08）

- 插入成片原声时停在半句（「所以才要买域名嘛，」后面还有「像 bookdot 点 cn 这种」），用户听成「半截没切干净的旁白」。规则：插入片段从完整句子开头到句号后的停顿；剪点用波形静音确定，转写整片复核。
- 痛点段第一条任务出现前有 2.5 秒只有背景，用户指出空白。旁白在讲的每一秒画面都要有对应内容。
- 背景不用纯黑，用有空间感的深色舞台（见 PROMO_STYLE.md）。
- 旁白「尾声卡字」的真正原因是**镜头切分点**：align.py 原来在「上一句末字结束 / 下一句首字开始」两个对齐时间的中点切开，对齐时间常偏晚 0.2–0.5 秒，切点落进下一句第一个字的起音里——上一段尾巴带半个字、下一段开头少半个字。已改为在句间窗口里按波形找最安静的点（80ms RMS 最小）再切，切口各加 10ms 淡入淡出；验收标准：每段开头和结尾 50ms 都低于 -45 dB。不需要重新配音。
- 插入的成片原声要选能体现「实操」的时刻（截图推近、光标点击 + 新手提问），不选概念插图段；画面要明确标出「成片原声」和正在说话的人，否则观众意识不到是原片。

## 公开发布（2026-10-08）

| 现象 | 根因 | 解决 |
|---|---|---|
| README 里想直接播放视频，提交进仓库的 mp4 只显示成下载链接 | GitHub 只在 README 里内嵌播放「网页上传」的视频（user-attachments，免费账户 ≤10 MB） | 先压一个 ≤10 MB 的版本，由用户在 GitHub 网页编辑 README 时拖进去；大视频（如 14 分钟成片）放视频平台链接，不进仓库 |
| 旧仓库名「还存在」 | 仓库改名后 GitHub 保留旧名重定向 | 用旧名新建仓库会覆盖重定向；本地 remote 要用新名 |
| 公开仓库漏了 CREDITS.md | 公开 .gitignore 写了整个 `articles/*/public/` | 只忽略媒体扩展名（png/jpg/wav/mp3/mp4） |
| 重跑导出会删掉公开仓库的 git 历史 | 导出脚本先整个删目录 | 清空时保留 `.git` |
| 用户在网页上改 README，提交作者是 GitHub 资料里的显示名 | 网页提交用账号资料，不走本地匿名身份 | 邮箱是 noreply 不泄露；导出前先 `git pull` 把网页修改同步回源文件，避免被覆盖 |
| 推送后页面还是旧按钮 | GitHub 页面缓存 | 刷新后再验收 |
| 宣传文案写「一键生成」 | 实际是多轮人工确认 + AI 写代码 | 宣传语必须属实；改成可验证的说法（「AI 写代码、全程聊出来、没用剪辑软件」） |

## 公开版冒烟测试（2026-10-09）

从 GitHub 全新克隆 → `./install.sh` → `new` → `fetch`（公众号）→ 写稿 → 替身配音（macOS `say`，不耗 Gemini 额度）→ `align` → `voicecheck` → `redboxes` → `shots` → `render` → `qa` → `chapters` 全部跑通。修了 4 处：

| 现象 | 根因 | 解决 |
|---|---|---|
| 公众号正文开头多一行 `style="visibility: hidden…"` | 正文正则从 `id="js_content"` 后面直接截取，带上了该标签其余属性 | 正则先越过标签：`id="js_content"[^>]*>` |
| `voicecheck` 崩溃（空张量） | 某句对齐结果落在镜头音频之外，切出来是空片段 | 过短的句子提示后跳过，不影响其他句子 |
| 片尾显示「你的公众号 / 频道名（显示在片尾卡片）」和「微信扫码」 | 安装时跳过公众号名，`new` 把示例占位文字写进了 meta.json | 占位文字视为未填；片尾没填公众号名就不显示这一行，没有二维码就不提「扫码」 |
| `chapters` 静默输出空文件 | meta.json 没写 chapters | 给出提示并退出 |

- 新版 npm 默认不执行依赖的安装脚本（esbuild 会有提示），实测不影响 Remotion 渲染。
- macOS `say -v Reed` 默认选的不是中文版本（只输出 0.01 秒静音）；做替身配音要写全名 `Reed (中文（中国大陆）)`。

## 抓取来源扩展（2026-10-09）

- 新增「其他网页文章」：readability（浏览器「阅读模式」同款算法）提取正文；懒加载图片先把 `data-src` / `data-original` 等换到 `src`；按出现顺序下载，宽或高 <80px 的图标/表情丢掉。实测：阮一峰周刊（44 图）、少数派、CSDN、Python 文档、GitHub Blog、dev.to、Substack、Wikipedia 正常；**知乎、Medium 返回 403**，提示改用 Markdown 导入。
- 本地 Markdown 导入会把 `![](…)` 引用的本地图片或网络图片一起导入并编号（原来只有文字）。
- 重新抓取前清掉上一次抓的编号图，否则换文章后新旧图片混在一起。
- 写代码要兼容 Python 3.10–3.12（install.sh 支持的范围）：f-string 的花括号表达式里不能有反斜杠（3.12 才允许）。
- 外文文章能抓，但口播、配音风格和文档都按中文调过；做英文视频要另配写稿指南和配音风格（后续迭代）。
