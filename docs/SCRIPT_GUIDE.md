# 口播脚本写作指南（双人对话）

口播的目标：**讲得对 → 听得懂 → 愿意听下去**。下面的规则提炼自漫行书海在真实成片中反复人审打磨出的口语化口播规则。

## 1. 为什么是双人对话

2026-10-05 盲听同一段讲解：edge-tts「一听就是 AI」；Gemini 单人「有真人感但不如对话」；**Gemini 双人对话最自然**。
自然感主要来自**稿子本身是对话**，其次才是音色。用户也明确过：去掉提问人后，承上启下和替观众提问的作用会丢失。

| 角色 | 音色 | 作用 |
|---|---|---|
| A 主讲（生成时角色名「主讲·女」） | Callirrhoe | 懂行的朋友，用文章自己的比喻讲清楚 |
| B 提问（生成时角色名「提问·男」） | Puck | 替观众问出卡点（「没备案行不行？」「IP 怎么查？」），承上启下，复述确认 |

## 2. 结构

- **开场**：第一句就让问题发生（如「我的网站弹了个 402」），不寒暄。开场提出的问题，结尾要回答。
- **地图**：步骤多的教程，先用一张总图把全流程过一遍，再逐步讲。
- **每一步**：概念（为什么要做）→ 操作（点哪里、填什么）→ 验证（怎么知道成功了）→ 常见卡点。
- **过渡**：前一个答案自然引出下一个问题，由 B 问出来；不用「接下来我们讲第二部分」。
- **结尾**：回答开头的问题 + 一句带得走的话；最后一句引导去看公众号文章（片尾卡片配合）。
- 时长参考：约 5.3–5.5 字/秒，4500 字 ≈ 14 分钟。做成**一个完整视频**，用视频平台的分段章节方便跳着看（用户 2026-10-06 决定不拆集）。

## 3. 写法规则

1. **为听而写**：短句、口语，一句只说一件事。念出来不顺的句子就改。
2. **沿用文章的比喻**（房子、门牌、管家……），不另造新比喻；比喻的理解成本必须低于原概念。
3. **先懂再命名**：先说它在干什么，再给专业名字（「对暗号的小本本」→「这就是 DNS」）。
4. **操作说动作**：「点『添加记录』」「复制标着『公』字的那个」，与截图上的按钮文字完全一致。
5. **命令不念全文**：口播说它在干什么（「让搬运工去 GitHub 拉货」），命令交给画面上的代码面板。
6. **长串交给画面**：URL、IP、路径只念关键部分并解释含义。
7. **事实锁定**：数字、价格、步骤以原文为准；原文没有的补充要在关卡 1 向用户标出。
8. **新手的问题要真**：B 问的应该是观众真会卡住的地方，不是捧哏。
9. **一个知识点只完整讲一次**，后面直接用。

## 4. 念法规范（TTS 会照字面念）

| 内容 | 写法 | 原因 |
|---|---|---|
| IP | 「四七点九八点几点几」 | 写数字会被念成「四十七点九十八」（用户要求逐位念） |
| 域名 | 「bookdot 点 cn」 | |
| @ | 「艾特符号」 | |
| 端口/状态码 | 「五千」「二百 OK」「四零四」 | 按人习惯的说法写 |
| 英文按钮/命令 | 保持原文（Push、nslookup、Build completed successfully） | |

字幕会自动把念法换回写法（`engine/src/Video.jsx` 的 `DISPLAY` 表），新出现的念法要加进去。

## 5. storyboard.json 格式

```json
{
  "title": "视频标题",
  "speakers": {"A": {"role": "主讲", "voice": "Callirrhoe"}, "B": {"role": "提问", "voice": "Puck"}},
  "scenes": [
    {
      "id": "s03_dns_concept",          // 唯一 id，shots.py 用它
      "title": "第 3 步：DNS 是什么",    // 显示在画面左上角
      "visual": "DNS 插画分区推近……",    // 给写画面的人看的意图说明
      "images": ["018"],                 // 计划使用的图片编号
      "lines": [["A", "台词……"], ["B", "台词……"]]
    }
  ]
}
```

镜头（scene）按「一个小知识点 / 一个操作段」划分，一般 15–60 秒，3–9 句。
